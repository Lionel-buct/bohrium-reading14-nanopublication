# 断言拆解与证据规则

## 1. 原子性判据

一条 Nanopublication 断言只有满足以下条件才可接受：

1. 能明确回答“谁对谁做了什么关系”；
2. 能单独判断真假，不依赖同一段中的另一个结论；
3. 主体和客体方向明确；
4. 条件、时间、剂量、样本、对照和统计限定没有被删除；
5. 关系类型与原文证据强度一致；
6. 改写成反事实后，仍能被同一条证据直接检验。

不满足时，应拆分或标记 `unresolved`，不能靠摘要化掩盖问题。

## 2. 复合句拆解

### 并列结构

原文：

> Treatment X reduced Y and increased Z.

拆为：

- Treatment X reduced Y.
- Treatment X increased Z.

每条分别绑定最小证据。若同一句能同时精确支持两条，可以复用同一引文，但必须分别判定每条断言。

### 因果链

原文：

> A activates B, which causes C.

可拆为：

- A activates B.
- B causes C.

除非原文直接报告 `A causes C`，否则不能补出第三步。来自同一段落的间接支持应标为 `indirect_support`，并说明推理链。

### 条件与限定

原文：

> In the tested concentration range, X reduced Y; no dose-response was established.

拆为：

- 在测试浓度范围内，X 降低 Y。
- 该研究没有建立剂量-反应关系。

不得写成“X 在所有浓度下降低 Y”。

### 非显著与未报告

- `p = 0.41` 支持“未观察到显著变化”，不等价于“证明无效应”。
- 原文没有报告某项数据时使用 `not_reported`；不能写成阴性结论。
- 只有作者明确报告“无变化”或统计检验未支持差异时，才使用 `no_change`。

### 相关与因果

- `associates_with`：只支持相关关系。
- `causes`：需要实验、机制或明确因果推断支持。
- `predicts`：需要预测关系或预测性能指标。
- `outperforms`：必须保留比较对象和指标。

## 3. 证据最小充分性

### 最小

优先选择能独立支持断言的单个句子、表格行、图注或公式片段。

### 充分

证据必须包含：

- 关键主语和宾语；
- 方向或符号；
- 数值或统计量；
- 条件和范围；
- 对照或比较基线（比较型断言必需）。

### 扩展

以下情况允许 `expanded_for_context`：

- 单个数字没有单位或基线；
- 图注依赖相邻方法段说明；
- 引用句需要前一句定义缩写；
- 表格值需要表头才能理解。

扩展证据仍应在 `sufficiency_rationale` 解释为什么不能更短。

## 4. 直接与间接证据

| 类型 | 使用条件 |
|---|---|
| `direct_support` | 引文本身足以支持或反驳断言 |
| `indirect_support` | 需要明确推理步骤或多个片段共同支持 |
| `context` | 只提供背景、方法或范围，不单独支持主结果 |
| `contradiction` | 与断言方向、数值或范围冲突 |
| `complementary` | 与另一片段共同构成完整证据 |

不能把 `context` 当作结果证据。不能把“同一论文中出现过”当作直接支持。

## 5. 来源追溯

每条断言至少记录：

- `source_id`
- 文件路径与 SHA-256
- 页码 / 段落 / 块 ID
- 字符区间
- DOI、标题、作者、年份（有则记录，无则 `null`）
- 版本或案例输入版本

跨图表证据必须分别记录图表页、图注页或表格块的定位。

## 6. 去重与合并

去重键：

```text
normalized_assertion_text | subject_name | relation | object_name
```

处理规则：

- 完全相同的断言：保留信息更完整、证据更直接的一条，另一条写 `duplicate_of`。
- 主体相同、客体不同：不是重复，保留。
- 条件不同：不是重复；条件必须进入 `conditions`。
- 同一断言的不同来源：保留多条证据，并用 `complementary` 或 `supports` 记录来源关系。
- 相反方向：不能合并；若存在冲突，进入 `conflicts`。

## 7. 关系方向检查

每生成一条关系，执行以下检查：

1. 读成 `subject -> relation -> object`。
2. 与原文句法方向比较。
3. 若原文是被动句，先恢复主动方向。
4. 比较型断言必须显式记录基线和指标。
5. 因果型断言必须确认原文没有使用 `associated with`、`may`、`suggests` 等弱化表达。

## 8. 证据冲突

冲突包括：

- 两个来源报告相反方向；
- 同一来源不同图表数值不一致；
- 断言写“显著”，证据显示“不显著”；
- 来源范围小于断言范围；
- 页码/段落定位指向不同结论。

处理：

1. 不删除冲突来源；
2. 在 `conflicts` 写明冲突类型、来源和定位；
3. 将断言极性设为 `inconclusive`，或将结论限制到可支持范围；
4. 在 `status_reason` 说明人工判断点。

## 9. 机械校验与语义校验的边界

`validate_nanopubs.py` 能检查：

- 字段完整性；
- 词表映射；
- 引文是否能在文本中定位；
- 页码、块和字符偏移；
- 证据长度和重复项。

它不能检查：

- 关系是否在科学上正确；
- 主体和客体是否在领域上等价；
- 证据是否足以支持完整因果解释；
- 引用是否被断章取义。

因此最终结果必须保留 `semantic_review_required: true`，不能把机械通过写成科学证明。

## 10. 示例使用规则

`examples/assertion-samples.json` 包含 20 条合成示例，仅用于展示字段、关系方向和证据绑定方式。不得把这些示例当作正式案例的答案、评分依据或真实论文内容。
