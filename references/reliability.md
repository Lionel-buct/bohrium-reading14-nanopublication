# 可靠性与异常处理

## 运行前探测

先运行 `runtime_probe.sh --create-dirs`。`blocked` 表示缺少 Python 3.9+ 或 PDF 文本后端，必须先修复；`partial` 表示 OCR、渲染或 DOCX 能力不完整，应使用文档化的降级路径并把受影响页面写入 `unresolved`。

## 1. 扫描版 PDF 无文本层

处理顺序：

1. `prepare_case.py --render-empty-pages` 将无文本页渲染到 `/app/work/rendered/`。
2. 使用运行时 OCR 工具识别目标页。
3. 识别结果写成 `/app/work/ocr/<source_id>/p0001.txt`。
4. 运行 `merge_ocr.py` 合并并重建 `source_units.jsonl`。
5. 重新执行证据校验。

如果 OCR 置信度低、版面顺序错误或包含公式乱码，必须在 `unresolved` 标记，不能把 OCR 错误写成事实。

## 2. 原文件无法访问

- 记录缺失路径、来源 ID、案例中的声明位置。
- 状态设为 `unable` 或 `partial`。
- 不根据文件名、标题或领域标签补造内容。
- 不引用“记忆中”的论文版本。

## 3. 引文无法定位

校验器返回 `evidence_not_found` 时：

1. 确认是否来自错误文件；
2. 检查 PDF 断词和连字符；
3. 从 `source_units.jsonl` 重新复制原文；
4. 如仍找不到，将断言移入 `unresolved`。

不得调整页码、字符区间或引文来“让校验通过”。

## 4. 断词与排版噪声

PDF 常见问题：

- `Time-\nResolved`：归一键保留连字符并去除换行；
- 引号、破折号、全角半角：使用 NFKC 和空白归一；
- 页眉页脚重复：不要把重复页眉当作主要证据；
- 双栏顺序错误：按页面块人工检查，必要时使用页面图；
- 表格数值错位：优先引用表头和对应行，或引用图注。

## 5. 图表和公式证据

- 图：引用图注 + 必要正文说明，记录页码。
- 表：引用表头、对应行和单位；必要时拆成多条证据。
- 公式：引用公式及其变量定义；仅引用公式编号不充分。
- 跨页：同一断言使用多个 evidence 项，不能拼成来源中不存在的连续引文。

## 6. 冲突

同一材料内部或材料之间出现不一致时：

1. 保留所有证据；
2. 在 `conflicts` 写明冲突；
3. 断言 polarity 使用 `inconclusive` 或限制到有支持的范围；
4. 最终状态至少为 `partial`；
5. 说明人工复核点。

## 7. 输出字段缺失

- 先检查 `case_manifest.json.output_contract_required_fields`。
- 如果输入没有规定答案，允许 `task_result` 为空对象，但 `nanopublications` 不得为空。
- 如果必需字段无法从材料得到，放入 `unresolved`，由最终器将状态降级。
- 不得用空字符串伪装字段已完成。

## 8. 重复运行

- 每个来源使用稳定 `source_id`。
- 运行前保留上一版 `change_log`。
- 相同去重键只保留证据更强的一条。
- 新增来源或 OCR 文本后，重新校验，不复用旧证据位置。
- 旧结果如需替代，使用 `lineage.supersedes`。

## 9. 资源预算

运行时预算有限：

- 先建立来源注册表和证据单元；
- 先输出可用的 partial 结果，再逐步补充；
- 不为每个段落调用模型；
- 不为所有页重复生成渲染图；
- 只对断言候选附近做深度阅读；
- 控制单条断言和证据长度。

## 10. 失败时的最小可交付

即使无法完成全部任务，也应尽早写出：

- `case_id`
- `status`
- `status_reason`
- 已读取来源
- 已确认断言
- `unresolved`
- 可人工接管的文件路径和页码

部分真实结果优于伪造完整结果。
